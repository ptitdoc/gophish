# FEATURE-qrcode -- QR code of the recipient link in templates

## What it does
A phishing template can show the recipient link as a QR code. The QR code is
generated by gophish for each recipient, so it carries the recipient identifier
(`RecipientParameter`) like `{{.URL}}` does, and a scan is recorded as a click.

Usage, in the HTML of a mail template, two forms:

```
<img src="data:image/png;base64,{{.URL | qrcode | base64}}">
<img src="{{.URL | qrcode | attachment "invitation.png"}}">
```

The first writes the image inside the HTML as a data URI. The second attaches it
to the mail as an inline part named `invitation.png` and references it as
`cid:invitation.png`; mail clients display it more reliably (see "Limits").

## Template functions
`models.ExecuteTemplate` registers three functions on top of Go's built-ins
(`models/template_context.go`, `templateFuncs`):

- `qrcode`: string -> PNG image bytes of the QR code. An empty string is an
  error, so the mail fails instead of leaving with a broken image.
- `base64`: bytes or string -> standard base64 with padding.
- `attachment "<name>"`: bytes -> `cid:<name>`. In the text and HTML bodies of a
  mail, it also adds the bytes to that mail as an inline part whose Content-ID is
  `<name>` (tracker:dev:2611-003). Everywhere else it only returns `cid:<name>`.

`attachment` takes bytes only, so any function that produces bytes can feed it;
`qrcode` is the only one today. A plain string is a template error.

Every phishing content goes through `models.ExecuteTemplate`: mail subject, text,
HTML and headers, landing page, redirect URL, attachments, and the template
validation run on save (grep 2026-11-24). `controllers/route.go` renders only the
admin UI. One registration therefore covers every place a template variable works.

Reasoning: functions instead of a `.QRCode` context field. The PNG is computed only
for templates that use it, and any value can be encoded (`.TrackingURL`, a fixed
text).

The image is 256 px with medium error correction, fixed constants
(`qrCodeSize`, `qrCodeRecoveryLevel`). Reasoning: no template has needed another
size yet; a constant becomes a parameter when one does.

The library is `github.com/skip2/go-qrcode`, pure Go with no dependency.

## How a mail is built and sent
Read in the code on 2026-11-24; the `attachment` design rests on these facts.

- `mailer/mailer.go` `sendMail` reuses one `gomail.Message` for a batch of mails
  and calls `message.Reset()` before each `Generate`. `Reset` clears the headers,
  the bodies, the attachments and the inline parts (`gomail/message.go`), so one
  recipient's parts never leak into the next mail.
- `Generate` builds one mail for one recipient: `MailLog.Generate`
  (`models/maillog.go`) for a campaign, `EmailRequest.Generate`
  (`models/email_request.go`) for a test mail. Both render the subject, the
  headers, the text body and the HTML body separately, each through its own
  template execution.
- Manual attachments (added by the user to the template) go through
  `addAttachment`. Each one is templated again for every recipient by
  `Attachment.ApplyTemplate` (`models/attachment.go`), for some file types only:
  the `.xml` and `.rels` files inside `.docx`, `.docm`, `.pptx`, `.xlsx`, `.xlsm`,
  and the whole of `.txt`, `.html`, `.ics`. Other files are sent unchanged. A
  file with no template variable is detected on its first send and sent
  unchanged afterwards.
- `addAttachment` chooses the disposition by file extension alone: `.jpg`,
  `.jpeg`, `.png`, `.gif` are inline (`msg.Embed`), the rest are attachments
  (`msg.Attach`). It does not look for a `cid:` reference in the HTML.
- gomail gives an inline part the Content-ID `<name>` unless one is set
  (`gomail/writeto.go`), so `cid:<name>` in the HTML shows it. The Content-Type
  comes from the name's extension.

## The attachment function
A template function cannot reach the mail being built: `templateFuncs` is one
fixed map shared by every render. So each `Generate` creates a collector
(`templateAttachments`), renders the text and HTML bodies through
`executeMailTemplate`, which overrides `attachment` with the collector's `add`,
then embeds the collected files after the manual attachments
(`embedTemplateAttachments`, `models/maillog.go`). `ExecuteTemplate` keeps its
signature. Reasoning: the patch touches the two `Generate` functions by three
lines each and adds code next to the template functions, instead of changing a
function every phishing content calls.

Rules of the collector:
- The same name with the same content is attached once. Reasoning: the text and
  HTML bodies render separately and may both call it.
- The same name with another content is a template error. Reasoning: one
  Content-ID shows one file, so a second image would be lost silently.
- An empty name is a template error.

Outside the text and HTML bodies (subject, headers, landing pages, redirect URL,
template validation), `attachment` only returns `cid:<name>`. Reasoning: template
validation on save renders the HTML with the fixed map; a function that failed
there would refuse to save a valid mail template.

Choices made with the user (2026-11-24):
- A template function, not a magic name detected in the HTML
  (`<img src="cid:qrcode.png">`). Reasoning: it keeps the syntax of the data URI
  form, `base64` replaced by `attachment`, and needs no name to remember.
- The function is named `attachment`. Reasoning: it adds an attachment exactly
  like a manual one, generated at send time; same concept, same name.
- The file name is given by the user. Reasoning: some mail clients list inline
  parts by name, and the user decides what the recipient sees.

The mail now carries different inline parts per recipient. Manual attachments
already differ per recipient when templated (see above); only their names stayed
the same, and the name of an `attachment` part is fixed by the template too.

## Limits
Gmail and Outlook often block `data:` images. The recipient then sees no QR code.
The `attachment` form avoids this.

- Inside a manual attachment (`.html`, Office files), `attachment` only returns
  `cid:<name>` and attaches nothing: `Attachment.ApplyTemplate` renders with the
  fixed map.
- A manual attachment with the same name as an `attachment` part is not checked:
  the mail then carries two parts with the same Content-ID.
- On a template error, `Generate` keeps upstream's behaviour: a warning in the log,
  and the mail leaves with the partial render.
- Not checked yet (2026-11-24): whether the admin UI preview shows `cid:` images.
  A test mail shows them.

## Other ways to get a QR code
- **External QR service**, works without this feature:
  `<img src="https://api.qrserver.com/v1/create-qr-code/?size=250x250&data={{.URL | urlquery}}">`.
  Checked end to end on 2026-11-24 (the token reaches the QR content). Every
  recipient link, token included, is sent to a third party (goqr.me), and the image
  is remote: clients block it by default or fetch it through a proxy (Proton does).
- **Manual image attachment** referenced by `cid:`: gophish embeds `.png`, `.jpg`
  and `.gif` attachments inline, but sends image files unchanged for every
  recipient, so it cannot carry a per-recipient QR code. The `attachment` function
  covers this case.

## Admin UI help
The template form shows a help block under the HTML editor, before "Add Tracking
Image" (`templates/templates.html`), listing `{{.URL}}`, `urlquery`, `qrcode`,
`base64` and `attachment`, and the attachment file types that are templated. The braces are written as HTML entities. Reasoning: the admin page is
itself rendered by `html/template`, which would execute literal braces.
